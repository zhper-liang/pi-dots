# 产品定义与领域语言

## 定位

Pidot 是本机运行的多机器人个人助理。用户可以直接找某个机器人做事，也可以让主管 pipi 组织多个机器人协作。网页上的手动操作和对话里的自然语言操作的是同一批日程和待办，结果、确认和执行责任都能追溯。

当前是本地单用户的 Node 服务加电脑网页，不是云端多租户服务。能做什么、不能做什么见 [MVP 能力与限制](mvp-scope.md)，实现见[架构总览](../architecture/README.md)。

## 领域语言

| 名词 | 意思 | 不要混淆 |
|---|---|---|
| 机器人（Bot） | 长期身份：名字、人格、版本化配置、能力开关、自己的主会话 | 除主管外地位相同，预置和自建只是初始配置不同 |
| 主管（pipi） | 管理机器人和协调协作的机器人，id 是 `chief` | 不能停用自己 |
| 主会话 | 每个机器人一个的日常对话 | 只能“清空并开始新会话”，不能普通删除 |
| Task | 一段可恢复的执行，带输入、运行配置、等待、用量和结果 | 不是待办事项 |
| 任务卡 | Task 的目标、执行者、主管、完成标准、阻塞和结果 | |
| 群聊 | 管理员机器人和成员共享必要上下文的空间 | 定向共享，不是广播 |
| 待办（Todo） | 可完成的事项 | 截止时间不占日历时段 |
| 日程（Event） | 有起止和时区的安排，保留本地或外部来源 | |
| 日历和任务列表（Source） | 已连接的业务数据来源，本地或飞书、Google | 随「日程与待办」分给机器人，可单独收窄 |
| 操作（Operation） | 一次写命令的请求身份、参数、确认、状态和回执 | 不需要先有聊天 Task |
| 计划（Schedule）与触发（Occurrence） | 何时做什么，以及某一次具体的触发 | 计划存在不代表已经执行 |
| 提醒、通知 | 对具体目标版本的提醒，以及应用内收件箱条目 | 已读不等于真的送达 |
| 能力 | 机器人能用的工具：固有能力加 Skills / MCP / 工具集开关 | 规则见[能力与权限](../architecture/capabilities.md) |
| 人格、记忆、共享偏好 | 每个机器人的人格和记忆文件，所有机器人共用的用户偏好 | 见[记忆](../architecture/memory.md) |

## 界面结构

| 页面 | 内容 |
|---|---|
| 首页 | 主管的主会话；输入即发给主管 |
| 机器人 | 可搜索的目录（`#bots`）；点卡片进主会话，点齿轮进设置 |
| 机器人设置 | 「能力」（Skills / MCP / 工具集三栏开关）、「记忆」（人格、记忆、共享偏好、整理状态）、「设置」（外观、模型、停用；高级里收窄日历和任务列表） |
| 新建机器人 | 只需名字，其余可选；默认空白，模板折叠可选 |
| 事项 | 「日历 / 定时任务 / 执行记录」，默认今日日历；定时任务一个列表列出所有机器人的任务 |
| 通知 | 「需要你处理」（确认、补充、跳过记录）和「提醒」（发现、自动改动、提醒、定时任务结果） |
| 设置 | 「连接 / 模型 / 自动化 / 偏好 / 高级」；飞书、Google、MCP 在同一个连接列表；模型可登记多个供应商 |

对话里，机器人回复按 Markdown 渲染；两段回复之间的工具调用折成一行“调用了 N 个工具”，展开看每个工具，再展开看参数和结果。界面不显示内部编号（调用 ID、版本号、requestId、原始 JSON），其他卡片用一句话说结果。旧的 Todo 数据和 API 保留，独立待办页已收起。

## 用户怎么用

1. 和任意机器人持续对话，或让主管创建、配置、停用、组织机器人。
2. 在群里由管理员协调，用单目标 @ 派活和收结果。
3. 在网页直接管理日程、定时任务、执行记录和收件箱。
4. 在主会话里直接查和改同一批事项；长任务派给独立 Task。
5. 让定时任务或事件触发在后台做事；需要用户决定的步骤会跳过并记下来。关闭网页不影响已保存的计划。

## 一致性原则

本地事项以本地为准，外部事项以外部为准，缓存不能冒充写回成功。网页和 Agent 共用业务服务。恢复时复用原 Task、请求和回执；结果不明时先核查，不能用新请求或清空记录消除不确定性。

## 演进边界

支付、多用户和多租户、云端常驻、手机 App、系统推送都不在本版。新连接器、权限扩张、运行环境或交付范围的变化要用户单独确认，历史候选计划不算授权。
