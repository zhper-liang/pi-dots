# 产品定义与领域模型

## 定位
Pidot 是多 Bot 持久化个人助理系统：用户可以直接委托专业 Bot，也可由 Chief 组织多个 Bot 协作。原生工作区与自然语言对话操作同一批业务对象，结果、权限、审批与执行责任可以追溯。

当前交付形态是本地单用户 Node 服务与电脑网页，不是云端多租户服务。云端长期运行和手机交互是演进方向，不是当前能力。具体支持范围以 [MVP 能力与限制](mvp-scope.md) 为准。

## 领域语言
| 对象 | 定义与边界 |
|---|---|
| Bot | 长期身份、职责与版本化配置；拥有独立会话、工具分配和授权范围 |
| Chief | 管理Bot与协作入口；普通管理按现有规则执行，管理权转授/能力配置需精确确认，不能停用自身 |
| Conversation | 用户与 Bot 或群的持续交流空间，不等于单次模型调用 |
| Harness Task | 持久化执行身份，承载输入、配置快照、限制、等待、结果与恢复；不是业务待办 |
| Task Card | 工作目标、主管、执行者、完成标准、阻塞和结果的责任记录 |
| Group | 管理员 Bot 与多个成员共享必要上下文的协作空间；定向共享而非无边界广播 |
| Todo | 可完成的业务事项；截止日期不自动占用日历时间 |
| Event | 有起止与时区的日程，保留本地或外部来源身份 |
| ItemLink | 待办与日程的显式关系，保留两端引用与版本，不自动合并或级联删除 |
| Operation | 一次业务命令的请求身份、参数、批准、状态与回执，不要求先创建聊天 Task |
| Schedule | 持久化的执行时间规则与动作定义，不代表已经执行 |
| Occurrence | 某个计划版本在某一 UTC 触发点的一次运行记录 |
| Reminder | 对具体目标版本的提醒定义；目标变更后重新计算触发 |
| Notification / Delivery | 应用内通知及处理记录；记录、已读与真实送达不是同一个事实 |
| Source / Grant | 业务来源与用户来源许可；Bot 通过实时工具/资源分配获得能力，stdio client 另有独立范围 |

## 用户工作方式
1. 与任意专业 Bot 持续对话，或让 Chief 创建、配置、停用和组织 Bot。
2. 在群内由管理员协调；使用单目标 @ 发起有来源边界的工作和结果回报。
3. 在网页直接管理本地待办、普通日程、来源、审批、计划、执行历史与收件箱。
4. 在 Bot 主会话直接查询和修改同一业务对象；工具组默认开，写入直接做，长任务派给独立 Task。
5. 由后台计划记录提醒或启动限定来源和工具的 Agent 工作流；显式启用写入后按实时规则执行，需询问的步骤跳过并记明；关闭网页不取消已保存计划。

## Bot 目录与详情
- 左栏「机器人」打开可搜索的 Bot 卡片目录（`#bots`），停用 Bot 保留并明确只读；新建进入独立模板选择/名字表单（`#new-bot`），只填名字即可。
- Bot 详情沿用 `#bot=<id>`，提供对话、工具、Skills、MCP、记忆、设置、任务入口；`tab` 可刷新恢复，切换标签不销毁输入和配置草稿。
- 对话直接显示该 Bot 原主会话，不新建 Task；规则复用实时工具组开关，设置集中职责、模型、来源、头像/颜色与停用。记忆仅为 T11 占位，不宣称已实现三文档记忆。
- Skills 展示全部已注册项，使用该 Bot 主 Task 的实际依赖检查结果；无法加载和缺失工具/资源保留原因，不因展示而扩张权限。
- MCP 标签只展示/发放当前 Bot 的本机 stdio 凭证，设置页全局入口保留；停用后不能发新凭证，已有凭证仍可撤销。
- 任务按 `task.bot.id` 展示原独立 Task（含归档）与例行任务，不把群聊或主会话算作独立任务。打开 Task 沿用原 hash/身份，浏览器后退回原标签；停用保留历史和已发生结果。

## 事项与通知
- 「事项」保留日历与自动化常驻入口；默认今日日视图，独立待办页和今日待办块收起。既有Todo数据、API与关联不删除，旧todos链接落到日历；截止日期不当日历占时。
- 自动化可选择 Bot，复用该 Bot 的例行任务创建、测试运行与历史；全部定时计划、只读简报和执行记录仍可达。切换标签或 Bot 不销毁草稿和原请求。
- 「通知」宽屏为「需要你处理」「事项提醒」两栏，窄屏按同顺序纵排。审批、阻塞、无人值守遇到 ask 而跳过的步骤在前栏；主动发现、自动执行记录、关联提醒、例行结果在后栏。
- 通知保留标题、时间、原因、动作及原 Task 链接；技术标识/原始字段放在折叠诊断。跳过记录不变成可批准操作，不自动重试；权限撤销后不展示来源派生收据。
- Chief 主会话及检测卡投递不变。通知 recorded/read 只说明应用内状态，不代表微信、QQ、系统推送或用户实际收到。提醒管理表单与执行历史保留在通知区的折叠入口。

## 权限与责任
- Bot 页按工具/MCP/Skill实时分配启停，写入确认独立保存；新Bot业务工具、能力与来源为空白，不按名字推人格或业务角色。旧Bot原分配、撤销与规则保留；实际可用取已登记、当前分配、有效来源的交集并扣除撤销，不存在能力池、Bot Grant、档位或Task权限epoch/快照匹配。
- Task 固定模型、提示词等运行配置，工具、资源和规则实时读取；新增、撤销和重授都从已有 Task 的下一次调用起生效，权限不需配置迁移；历史仍复核来源，外部来源失效时旧派生上下文可退役并清摘要，真实用户输入与审计保留。
- local 为所有者隐式完整许可，外部来源保留用户许可和 readScope；Bot 需要相应工具与来源资源。busy-only 只返回时段，不泄漏标题与正文；stdio client 另受自己的范围、到期和撤销约束，凭证在设置页管理。
- 已分配传统业务写工具按独立确认规则裁决：allow直接执行，ask先问；包含删除。外部MCP调用、能力配置变更及管理权转授需要精确宿主确认，不因annotations或普通组开关免除。Chief可改自身配置，不能停用自身；未知工具拒绝，没有批量或每小时自动写入上限。
- 需要询问的动作绑定原操作、精确参数及认证用户决定；传统业务卡的“以后直接做”调整对应确认规则，MCP/配置Host不提供此免确认选项。全局暂停把allow写入降为ask，暂停中及unknown后重做也无“以后直接做”；无人值守遇到ask跳过并记录。
- 本地自动改动留记录并支持版本校验后的撤销；外部写入不提供撤销。取消、暂停、幂等、unknown 不盲重试和调用预算继续生效。现行取代关系见 [ADR-014](../decisions/README.md#adr-014-实时权限与直接做先问) 与 [ADR-015](../decisions/README.md#adr-015-工具组默认开开即直接做)。
- 协作请求经过目标主体与能力检查；主管验收、返工、阻塞升级和最终决定保留责任链。
- 取消或撤权停止后续工作，不把已经发生的外部效果伪装为撤销。

## 一致性原则
本地事项以本地持久化为权威，外部事项以 provider 为权威；缓存不能冒充写回成功。UI 与 MCP 共享业务服务。恢复优先复用原 Task、请求和回执；未知结果先核查，不能通过新请求或清空记录消除不确定性。

## 演进边界
邮件、外部待办、支付、完整长期记忆、多用户/多租户、云端与手机、系统推送都不由本版默认开放。新连接器、权限扩张、运行环境或交付范围变化须单独确认，不把历史候选计划当作授权。

实现约束见 [系统架构](../architecture/system-overview.md)、[技术决策](../decisions/README.md) 与 [接口契约](../interfaces/README.md)。

## 连接、会话与真实回执

普通会话删除采用持久标记和既有停止边界，不等同归档或物理擦除。主会话明确清空换新，旧上下文不带入新入口，独立子Task与原结果审计保留；当前主映射承接后续结果，连续清空/重启仍去重。

外部MCP客户端与Pidot对外stdio凭据是两个方向。官方SDK连接的配置、独立凭据、检查、目录、每Bot绑定和实际调用均进入已有Host/Harness；源发生变化要重新审阅，新工具不自动放行。Chief或实际显式获管理工具的配置Agent可以管理MCP/Skill，普通Bot不因名字、角色文本或自我请求取得管理权。缺凭据、缺依赖、unknown与ready分别显示，原setup可查/可受控续办，不能把保存配置当执行成功。
