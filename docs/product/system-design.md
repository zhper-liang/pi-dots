# 产品定义与领域模型

## 定位
Pidot 是多 Bot 持久化个人助理系统：用户可以直接委托专业 Bot，也可由 Chief 组织多个 Bot 协作。原生工作区与自然语言对话操作同一批业务对象，结果、权限、审批与执行责任可以追溯。

当前交付形态是本地单用户 Node 服务与电脑网页，不是云端多租户服务。云端长期运行和手机交互是演进方向，不是当前能力。具体支持范围以 [MVP 能力与限制](mvp-scope.md) 为准。

## 领域语言
| 对象 | 定义与边界 |
|---|---|
| 机器人（Bot） | 长期身份、职责与版本化配置；拥有独立会话、能力开关和可用日历/任务列表 |
| Chief | 管理Bot与协作入口；普通管理按现有规则执行，管理权转授/能力配置需精确确认，不能停用自身 |
| Conversation | 用户与 Bot 或群的持续交流空间，不等于单次模型调用 |
| Harness Task | 持久化执行身份，承载输入、配置快照、限制、等待、结果与恢复；不是业务待办 |
| Task Card | 工作目标、主管、执行者、完成标准、阻塞和结果的责任记录 |
| Group | 管理员 Bot 与多个成员共享必要上下文的协作空间；定向共享而非无边界广播 |
| Todo | 可完成的业务事项；截止日期不自动占用日历时间 |
| Event | 有起止与时区的日程，保留本地或外部来源身份 |
| ItemLink | 待办与日程的显式关系，保留两端引用与版本，不自动合并或级联删除 |
| Operation | 一次业务命令的请求身份、参数、批准、状态与回执，不要求先创建聊天 Task |
| Schedule | 持久化的执行时间规则与动作定义，不代表已经执行 |
| Occurrence | 某个计划版本在某一 UTC 触发点的一次运行记录 |
| Reminder | 对具体目标版本的提醒定义；目标变更后重新计算触发 |
| Notification / Delivery | 应用内通知及处理记录；记录、已读与真实送达不是同一个事实 |
| 日历和任务列表（Source）/ Grant | 已连接的业务数据与用户许可；随「日程与待办」分给机器人，可单独收窄；stdio client 另有独立范围 |

## 用户工作方式
1. 与任意专业 Bot 持续对话，或让 Chief 创建、配置、停用和组织 Bot。
2. 在群内由管理员协调；使用单目标 @ 发起有来源边界的工作和结果回报。
3. 在网页直接管理本地待办、普通日程、来源、审批、计划、执行历史与收件箱。
4. 在 Bot 主会话直接查询和修改同一业务对象；能力按工具集开关，启用后写入直接做，全局暂停时确认，长任务派给独立 Task。
5. 由后台计划记录提醒或启动限定来源和工具的 Agent 工作流；显式启用写入后按实时规则执行，需询问的步骤跳过并记明；关闭网页不取消已保存计划。

## 机器人目录与设置
- 左栏「机器人」打开可搜索的目录（`#bots`）；点卡片进入原主会话，不新建 Task，Chief 进入首页；点齿轮进入设置。
- 设置仅有「能力 / 记忆 / 设置」三栏（`tab=capabilities/memory/settings`）；不带 tab 或未知 tab 进入对话。切换时保留输入和配置草稿，不保留旧 tab 别名。
- 「能力」有 Skills / MCP / 工具集三个子栏和搜索，每项一个开关，只列本机已装、已连接的能力；不提供写入确认模式。系统级管理能力隐藏，Chief 的固有能力配置不显示开关。
- 新建只需名字，可选「负责什么」与模板；高级内选择能力，默认「日程与待办」「历史与回读」开启，Skills/MCP 关闭。创建后直接进对话；外观在设置里改。
- 「记忆」编辑人格、纠正/删除记忆，查看共享偏好；文件式记忆以 Markdown 为真源，按 ADR-019 对账。
- 「设置」集中外观、模型、停用；高级里只收窄已连接的日历和任务列表，技术字段与飞书面板折叠在末尾。stdio 凭证移到全局「设置 → 高级」。停用保留历史并只读。

## 事项与通知
- 「事项」仅有「日历 / 定时任务 / 执行记录」三栏，默认今日日历。旧 Todo 数据、API、显式关联保留，旧待办链接落到日历；截止日期不占日历时间。
- 定时任务在一个列表中列出所有机器人的任务，每行标机器人名；可创建、测试、暂停、恢复或取消。新建默认 Chief，停用机器人的行只读；原内部计划放技术信息，执行记录单列。
- 「通知」只有「需要你处理」「提醒」两块，宽屏并列、窄屏纵排。审批、补充和跳过记录在前，发现、自动改动、提醒、定时任务结果在后；保留原会话链接与操作。
- 提醒管理和原始字段保留在技术折叠内；跳过记录不变成可批准操作，不自动重试。应用内已读与外部推送仍是不同事实。
- 全局设置为「连接 / 模型 / 自动化 / 偏好 / 高级」；飞书、Google、MCP 是同一个连接列表，技术状态和 stdio 凭证在高级。

## 权限与责任
- 能力按 Skills / MCP / 工具集实时启停。新机器人默认 `tool:todos` + `tool:history`；创建时可覆盖，旧机器人按 [ADR-022](../decisions/README.md#adr-022-工具集只有开关来源跟着日程与待办新机器人带默认能力) 一次迁移。可用工具仍是已登记与当前分配的交集扣除撤销，无能力池、档位或 Task 权限快照。
- 「日程与待办」合并日历和待办工具；持有任一工具就获得所有已连接日历和任务列表，单机器人高级设置可收窄，收窄在重连后保持。连接/用户许可仍实时检查，busy-only 仍不返回正文。
- Task 固定模型名、提示词等运行配置，工具、日历和任务列表实时读取；新增、撤销和重授从已有 Task 的下一次调用生效，历史回读继续复核许可。
- 启用的写工具直接执行（含删除、外部 MCP 与对话能力配置），不再有「先问 / 直接做」设置。`PolicyRules` / `decide()` 保留；全局暂停把 allow 改为 ask，无人值守遇 ask 跳过并记录。unknown 后的重做与精确审批保护保留。
- 审批绑定原操作、精确参数及认证用户决定；卡片的「以后直接做」保留，暂停中和 unknown 后重做不提供。Chief 可改自身配置，不能停用自身；未知工具拒绝，预算和取消独立生效。
- 开 Skill 自动带上加载工具，不因此获得其声明的业务依赖；stdio client 另受自身范围、到期、撤销与机器人当前能力限制。
- 本地自动改动留记录，可在版本未变时撤销；外部写入无撤销。取消/撤权约束后续工作，协作主管验收、返工和阻塞升级仍保留责任链。

## 一致性原则
本地事项以本地持久化为权威，外部事项以 provider 为权威；缓存不能冒充写回成功。UI 与 MCP 共享业务服务。恢复优先复用原 Task、请求和回执；未知结果先核查，不能通过新请求或清空记录消除不确定性。

## 演进边界
邮件、外部待办、支付、完整长期记忆、多用户/多租户、云端与手机、系统推送都不由本版默认开放。新连接器、权限扩张、运行环境或交付范围变化须单独确认，不把历史候选计划当作授权。

实现约束见 [系统架构](../architecture/system-overview.md)、[技术决策](../decisions/README.md) 与 [接口契约](../interfaces/README.md)。

## 连接、会话与真实回执

普通会话删除采用持久标记和既有停止边界，不等同归档或物理擦除。主会话明确清空换新，旧上下文不带入新入口，独立子Task与原结果审计保留；当前主映射承接后续结果，连续清空/重启仍去重。

外部MCP客户端与Pidot对外stdio凭据是两个方向。官方SDK连接的配置、独立凭据、检查、目录、每Bot绑定和实际调用均进入已有Host/Harness；源发生变化要重新审阅，新工具不自动放行。Chief或实际显式获管理工具的配置Agent可以管理MCP/Skill，普通Bot不因名字、角色文本或自我请求取得管理权。缺凭据、缺依赖、unknown与ready分别显示，原setup可查/可受控续办，不能把保存配置当执行成功。
