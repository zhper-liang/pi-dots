# 运行与恢复手册

## 在线部署与启动
- 按[工程README](../../my-app/README.md)使用现有配置、Node≥22.22.1/pnpm 11.21.0；不复制/覆盖已有.env，不把凭证写进浏览器或VITE变量。
- 一个Node API实例+一个Harness+一个SQLite库，监听127.0.0.1。API在线时后台调度，与浏览器/聊天是否打开无关；停机时不执行，启动后依持久计划和misfire规则恢复。
- 不让两个进程同时打开同一库；生产库不用于验收。先停原实例再同库启动，保留WAL/SHM与审计，不用“清库”修复unknown。

## 日常操作
1. 连接后先“来源与状态”读取状态；本地用户许可在清单，飞书绑定沿用“助理会话”旧来源管理；日历来源中明确授权及配置只读同步。
2. 手动事项在清单/日历操作，保存看持久回执。外部先精确预览，确认来源/ID/版本/起止，再批准；候选不是已发送。
3. “审批与权限”单独管理Bot许可、受限MCP client和Agent建议。正文/忙闲权限互不混淆，用户授权不替Bot授权。
4. “定时任务”确认频率/时区/在线条件和只读预算；“执行记录”选择计划看Occurrence、attempts、错误、Operation/Task/Delivery。暂停/恢复/取消都有明确确认；当前Task单独处理。
5. “通知与提醒”创建精确目标/版本提醒；闭页后重新打开可读。记录或标已读不代表系统送达，旧群blocker仍留原Task。
6. 切页保留草稿和原requestId；unknown或网络结果不明时按原requestId查询，不新建相同写入，不靠空缓存推断失败。

## 故障与回滚
- 409：读取最新对象/版本后由用户重新判断，不自动覆盖。权限撤销：隐藏正文、停止未来动作，保留旧Task、Operation、审批、unknown与失败。
- 外部发送无回执：保留dispatching/unknown，禁止盲重试或删除资源“清账”；人工按精确外部ID核查并保留证据。
- 读/内部通知的安全有限重试与外部写unknown不同，不把前者策略套到后者。
- 回滚只禁用新工作区/计划入口（PIDOT_WORKSPACE_ENABLED=0并按既有启动说明重启），保留数据库记录，不降级覆盖schema、不删除审计/重开已结束Task。


### 周/月计划的回滚边界（T09）
周规则使用 ISO 星期（周一 1 至周日 7），月规则的短月取最后一天；DST 缺失时刻跳过、重复时刻只运行第一次。暂停期间不补跑。

旧版 `normalizeScheduleRule` 拒绝创建/修改 `weekly` / `monthly`，但旧版读取已经暂停的周/月计划不会因此拒绝。旧版恢复这些计划时，其旧计算逻辑可能把周/月误按每日运行。因此**不能仅暂停后降级**：须先在新版取消所有周/月计划、确认没有仍在执行的原 Task/Operation，再回滚应用；保留 Schedule、Occurrence 与审计，不手工删库或重写规则。旧版不能恢复这些已取消计划；需要时在兼容版本重新明确创建。

测试运行是只读验收，不投递结果通知；正式运行是否生成应用内通知由计划通知开关决定，不表示微信、QQ 或操作系统推送。

### 文件式记忆的开关与回滚（R2）
`PIDOT_MEMORY_FILES` 默认 `1`：人格、记忆和共享偏好在数据库同目录的 `bot-workspaces/` 下，可以直接编辑，Pidot 在下一次读取前导入；目录和文件权限会被收紧到 0700/0600。备份时把这个目录和数据库一起备份。

- 回滚：设 `PIDOT_MEMORY_FILES=0` 后重启。启动时把还没导入的手改收进台账一次，之后只用台账，行为与 R2 前相同；文件留在磁盘上不删。再设回 `1` 是一次普通对账，关闭期间两边的修改三方合并。
- 回退代码：R2 前的代码能直接读写新库。限制是旧界面不能改写手写条目（只能删除），注入里手写条目显示为 `[]`。
- 已知限制：写回会把文件整理成规范格式，丢掉手加的标题和注释；编辑器用打开很久的旧缓冲保存，会删掉期间新增的条目，修订历史可以找回；编辑器清空文件后停顿超过约 50 毫秒时可能被读到半份，下次对账补回，但补回的条目丢失原对话来源，显示为手写。

### Google 连接与 workspace-mcp（R3）
真实账号的手测由用户自己做；自动测试只用本机假服务。

1. 在 Google Cloud 控制台新建项目，启用 Calendar、Tasks、Gmail、Drive、Docs、Sheets 六个 API。
2. OAuth 同意屏幕选“外部”，发布状态设为“正式发布”（未验证，登录时会多一次“未经验证的应用”提示；停在“测试”时令牌 7 天过期）。
3. 新建“桌面应用”类型的 OAuth 客户端。
4. 在 Pidot “设置 → 连接 → Google”填客户端 ID 和密钥（也可用 `GOOGLE_OAUTH_CLIENT_ID`、`GOOGLE_OAUTH_CLIENT_SECRET`，环境变量优先，界面随之只读），勾选日历、任务和邮件与文件，点连接并在浏览器登录。Pidot 在另一台机器上时，把浏览器地址栏里的跳转地址粘回设置页。
5. 按第三轮计划的 `R3-05-OPS.md` 写 workspace-mcp 的环境文件并启动。必须设 `WORKSPACE_MCP_HOST=127.0.0.1`，否则它监听所有网卡。端口不是 8000 时在 `my-app/.env` 设 `PIDOT_WORKSPACE_MCP_URL`。
6. 对 Chief 说“接上 Google 邮件和文件，给某个 Bot”。设置页会显示 workspace-mcp 是否在运行、是否已连接。

- 断开：设置页断开会撤销令牌、删除本地凭据，所有 Bot 立即失去 Google 来源和 workspace-mcp 工具。
- 迁到服务器：停服务，复制数据库目录（含 `google/`），在服务器装同一版本 workspace-mcp 并用同一份环境文件，启动后在设置页检查一次连接。
- 已知限制：workspace-mcp 的写入结果不明时只记 unknown，是否重复发信要自己核对；重启后 workspace-mcp 连接要重新检查一次才可用。

### 第四轮升级（R4）

1. 停掉正在运行的 Pidot 服务。
2. **复制整个 `my-app/data/` 目录做手动备份**，包含 SQLite 及旁边的 `bot-workspaces/`、连接配置和凭据目录；备份按本机秘密文件保管，不提交仓库。自定义数据库路径时复制其整个数据目录。
3. 更新代码，在 `my-app/` 执行 `pnpm build`，之后 `pnpm start:api`。生产入口会传 `r4Migration: true`，首次启动按 `ToolAccess.r4MigratedAt` 自动迁移一次，后续启动不重跑；嵌入与普通测试 store 默认不迁移。
4. 打开机器人设置、创建页与事项/通知/全局设置，按[第四轮清单](../../plans/active/r4-simplify/README.md#2-目标与验收)验收。真实 Google / 飞书账号手测仍由用户自己做。

一次迁移依序完成：
- 对已开日历或待办任一工具的机器人补全合并后的「日程与待办」工具集，并清除这些工具的撤销标记。
- 为已启用 Skill 的机器人同步加载所需工具。
- 为持有「日程与待办」的机器人分配所有已连接日历和任务列表，保留单机器人收窄。
- 删除非 preset 的 ask 规则，保留 deny / allow；写入直接做，全局暂停仍要求确认。
- 从全部分配及排除项移除 `mock:personal`，后端模拟代码保留。
- 日程、待办预设说明仍等于旧文案时更新，用户改过的说明保留；打开记忆文件后，仅仍等于旧原文的人格同步更新。
- 记录 `r4MigratedAt`。不自动备份、不新增回滚开关，不手工删库或重写历史。

注意：飞书重新绑定产生新的 `feishu:` id 时，旧 id 上的单机器人收窄不作用于新 id，需在该机器人的「设置 → 高级」重新关闭。

## 验证与适用性
自动测试仅使用临时/隔离库，真实强杀使用隔离子进程，不对真实 provider 人为制造未知写入。正式库不用于验收；不得通过清库、清审批或重新授权掩盖历史问题。

功能边界以 [MVP范围](../product/mvp-scope.md) 为准。历史真实跨租户豁免保留，不将其作为已验证多租户保证。新增连接器、通知渠道或部署环境前重新评审 [技术决策](../decisions/README.md)。
