# 能力与权限

本文是“机器人能用什么、用的时候要不要问”的唯一正文。来历见 ADR-014、ADR-018、ADR-021 至 ADR-025；这些 ADR 记录了当时的选择，现行规则以本文为准。

## 两步判断

每次工具调用都过两步，都在服务端，每次实时计算，不看 Task 创建时的快照：

1. **能不能用**：这个工具在不在机器人当前的可用集合里（`tools.mjs` 的 `toolSets()`）。不在就拒绝。模型只看得到可用集合里的工具，但隐藏 schema 不算权限控制，派发时还会再查一遍。
2. **要不要问**：可用的写工具交给 `policy.mjs` 的 `decide()` 裁决 allow / ask / deny。

### 已有会话中的变更

能力保存后，已有会话在下一次模型调用时使用当前工具定义；派发工具前还会复核当前权限。宿主每轮提供当前能力与来源摘要，明确历史回复或压缩摘要中的“没有权限”结论可能已经过期。模型请求已发出时不改写在途请求，新能力在后续步骤可见；撤权不能撤回已经派发的操作。

能力页区分“已开启”和“当前可用”，缺凭据、连接失败、机器人停用、日程工具未分配来源时返回具体原因。这个状态用于说明配置，实际调用仍要复核连接和来源许可。网页保存确认后通知关联页面重新读取，并清除旧工具标签缓存。进入页面、回到窗口、恢复网络和后台定时检查都会自动同步；正常状态没有刷新按钮，同一身份下后台读取保留内容，失败时提示自动重试并提供重新读取。同步不重跑任务、调用模型或清空草稿。历史来源保护继续生效：已经使用的来源被撤销时，不能通过刷新把旧正文重新送入模型。

## 能不能用：可用集合

```text
可用工具 = 固有能力 ∪ (已安装 ∩ 当前分配 − 已撤销)
```

**固有能力**每个机器人都有，不出现在开关里，也关不掉：

| 能力 | 工具 | 范围 |
|---|---|---|
| 本机操作（ADR-024） | `bash`、`read`、`write`、`edit` | 所有 Task；相对路径从 `bot-workspaces/<botId>/` 解析，用服务进程的系统权限 |
| 回查（ADR-025） | `task_history_read`、`tool_result_read` | 所有 Task；只读本 Task 的记录 |
| 记忆 | `memory_read`、`memory_edit` | 所有 Task；见[记忆](memory.md) |
| 主会话专属 | `session_search`、`session_history_read`、`memory_review` | 只在主会话 |

**可选能力**在机器人设置的「能力」页三栏开关：Skills、MCP、工具集。工具集来自 `tool-groups.mjs` 的 `TOOL_GROUPS`：

| 工具集 id | 名字 | 内容 |
|---|---|---|
| `todos` | 日程与待办 | 日历和待办的读写、提醒、定时任务提案 |
| `collaboration` | 机器人协作 | 查看其他机器人、派任务、验收、共享信息 |
| `reports` | 进度与阻塞 | 提问、上报、查看派出任务的进度 |
| `automation` | 自动化控制 | 一键暂停全部自动化，只在主会话 |
| `capabilities` | 能力配置 | `mcp_manage`、`skill_manage` |
| `skills` | Skills | Skill 的加载工具；开任一 Skill 时自动带上，关掉最后一个时移除 |
| `bots` | 机器人管理 | `bot_manage`，只给主管 |

新机器人默认空白：职责为空，可选能力全关（ADR-023）。除主管外所有机器人地位相同，名字和模板不带任何权限。主管额外有机器人管理和能力配置的固有职责，且不能停用自己。

### 日历和任务列表跟着「日程与待办」

开着 `todos` 中任一工具的机器人，自动拿到所有已连接的日历和任务列表（`workspace:*`、`feishu:*`），在 `resource-sharing.mjs` 分发。能力页把「使用范围」嵌在「日程与待办」工具集内，以勾选框选择来源，飞书连接管理就在对应来源行。工具集关闭时保留已选范围并禁用勾选，重新开启后生效；它不自动断开所有机器人共享的连接。工具集开关显示「部分」表示只启用了该组的部分工具，不表示来源连接异常。

来源排除项存在 `ToolAccess.excludedResources[botId]`，同一资源恢复连接不会重置排除项，新绑定日历按新来源规则分发。单独持有 `routine_propose` 不分发来源（ADR-022）。

普通会话中，委派时只交给执行者目标和完成标准，不要求双方拥有相同来源范围；执行者真正调用来源工具时仍按自己的当前能力检查。委派结果以及同一机器人独立任务的摘要默认交给发起者，即使发起者没有直接访问来源的工具，或在自己的直接工具范围中排除了该来源；这不授予发起者直接读取或写入来源的能力。作者使用的来源、外部 MCP 目录版本和用户许可仍需有效。群聊共享沿用独立的成员与来源检查。

连接本身就是用户许可：连上飞书或 Google 时同一事务写入完整的用户 Grant（ADR-021）。Grant 和 `readScope` 仍在，用于用户收窄；只给忙闲（busy）的来源在服务端只返回时段，不返回正文。

## 要不要问：decide()

| 情况 | 结果 |
|---|---|
| 读工具、内部协作工具 | allow |
| 未登记的工具或动作 | deny |
| 写工具，有匹配规则 | 按 tool / action / sourceId / type 取最具体的规则；同样具体时 deny > ask > allow |
| 写工具，没有规则 | allow，直接执行 |
| 删除 | ask，每次都问；已有 allow 规则也不跳过，显式 deny 仍是 deny |
| 全局暂停中 | 写入的 allow 降为 ask |

“删除”指工作区 `workspace.prepare_change` 的 delete、`calendar_feishu_delete_event`，以及名字或 action 里明确表示删除的外部 MCP 调用。原生 `bash` 不按脚本内容推断删除。

ask 怎么处理取决于有没有人在：

- **用户在场**：出确认卡，绑定原操作、精确参数和版本；本地提案 5 分钟有效。用户同意后再复核一次才执行。卡上的“以后直接做”会打开该工具所在工具集（`openGroup()`）；删除、暂停中、结果未知后的重做不提供这个按钮。
- **无人值守**（来源是例行任务、事件触发、检测器）：不出卡、不等待，直接跳过，在工具结果和运行记录写“已跳过：这一步需要你来做。”

全局暂停还会停掉例行任务和事件触发，恢复后不补跑。机器人可以暂停，恢复只能由用户操作。

## 专用运行的限制

| 运行 | 能用什么 |
|---|---|
| 例行任务 | 只有工作区读工具和回查，限定原来源；显式 `writes=true` 才开放工作区改动。不含本机能力和记忆工具 |
| 测试运行、旧只读简报、“帮我想办法” | 只读，不开放本机能力；“帮我想办法”每次最多 5 次模型、10 次工具调用 |
| 委派出去的子任务 | 看不到 `task_assign`，不能再委派 |

例行任务每次派发都实时复核机器人是否启用、读工具、来源和用户许可，失效就取消并记录原因。

## Skill

Skill 是工作方法，不是权限。开启 Skill 只自动带上加载工具，不授予它声明的业务工具（`allowed-tools` 只是声明）。机器人从简要目录自己选（`skill_activate`），或用户用 `/` 指定；每条输入处理完自动停用。目录合并内置 `server/skills/` 和用户 Skill 包；发现不等于分配，新 Skill 不会自动给旧机器人打开。导入的 Skill 固定来源、内容 hash 和版本（`skill-import.mjs`、`skills.mjs`）。

## 外部 MCP 工具和对话里的能力配置

已给某机器人打开的外部 MCP 工具和其他写工具走同一条 `decide()`（ADR-018）。外部来源的 schema 或 catalog 变了要重新审阅，正常重连不扩权。

主管（或宿主明确赋权的配置 Agent）可以在对话里用 `mcp_manage`、`skill_manage` 添加、绑定、停用 MCP 和 Skill，和设置页走同一个服务层（`capability-management.mjs`）。配置意图必须来自当前真实用户输入；缺凭据时让用户在安全表单里填，聊天里不传 Key；结果不明时只查原请求，不自动重派。连接本身见[外部连接](integrations.md#外部-mcp-客户端)。

## 副作用保证

本地自动改动留记录，版本没变时可以撤销；外部写入不能撤销。requestId 幂等、`unknown` 不盲重试、取消、暂停、调用额度这些保护和权限开关无关，一直有效（ADR-006）。
