日期：2026-11-01（Asia/Shanghai）。状态：**M01—M06 实现与本地验证完成，待用户验收**。

本轮实施依据是用户明确要求“创建6.1sol子agent完成计划”，授权完整实施 M01—M06 和子 Agent 协作；不含新依赖、正式数据、服务重启、真实供应商/账户及提交/推送。此前规划依据是用户要求“生成下一阶段改进计划”。前一阶段的模型容量、Pi压缩和记忆工具继续以[现有计划](../../done/2026-11-01-context-memory/README.md)为准；本计划承接一小时空闲、压缩触发、Task成果复用及Hermes研究后的改进。用户明确的要求与本计划的推荐决策分开记录；研究及源码依据见[findings.md](findings.md)。

## 目标与用户体验

用户主要与一个Bot的主会话交流。长任务交给Task执行后，其可靠成果能在后续相关问题中被主会话找到；稳定事实被保留，做事方法逐渐形成可复用Skill。用户可以查看、纠正或忘记已保存内容，无需每次重述背景，也无需逐条管理项目记忆库。

本阶段按信息用途控制粒度：少量长期事实、可回查的经历、按需加载的方法。项目名/路径/适用条件写在条目或Skill里，不为每个项目另建一层记忆空间。记住某项目的规则，不代表这条规则适用于其他项目。

| 记忆归属 | 推荐，沿用现有Bot边界 | 每Bot记忆由所属主会话的统一整理服务维护；用户通用偏好跨Bot共享 |

“主会话统一整理”指写入责任属于Bot，宿主运行专门的后台作业；不把整理伪装成用户消息，不强制唤醒主聊天的业务推理。作业以botId归属，通知投递到当前主会话；清空/重建主会话不会让候选写错地方。

直接用户在普通私聊Task中明确提出的记忆修改仍走现有用户修改入口；它与自动派生Task的写入权限分别校验，不因统一整理而要求用户再去主窗口重复一遍。

## 内容存放与取用

| 内容 | 存放位置 | 写入与取用规则 |
|---|---|---|
| 人格与职责 | 既有PROFILE.md | 只接受用户修改；自动整理不改人格 |
| 用户长期偏好 | 既有共享USER.md | 依据直接用户陈述；一次临时要求不升级成长期偏好 |
| 稳定环境事实、长期约定 | 既有Bot MEMORY.md | 精简记录，带适用对象、来源与更新时间；按当前问题选择注入 |
| Task进度、完成日志、临时线索 | 原始会话与Task压缩摘要 | 持久保留、按需检索；不占常驻记忆 |
| 可复用的方法与已验证经验 | 已有Skill体系中的学习产物 | 步骤、适用条件、验证方式和必要的注意事项；需要时加载 |
| 日程、待办、外部实时状态 | 原业务来源 | 使用对应业务工具查询/修改；长期记忆不替代实时来源 |

同Bot主会话和Task可读取该Bot有权读取的记忆。不同Bot的长期记忆不自动合并；共享偏好保持现状。Task自己的压缩摘要继续只服务该Task，主聊天通过结果回报或历史检索取得所需信息。

容量建议：本阶段先沿用既有文件硬上限（16384字符/64条）和总注入预算（默认6000字符、绝对上限12000，仍受模型余量约束），增加精简与相关性取用；不把旧文件强制裁成Hermes的2200/1375字符。人格、偏好和记忆的实际占用分别可见；不足时保留整个条目并按需读取，不截掉半条事实。中文场景的更小默认值在验收样本上评估后再决定。

## 整理触发与执行契约

| 触发 | 登记时机 | 执行方式 |
|---|---|---|
| 用户明确保存/纠正/忘记 | 当前用户工具调用 | 立即校验并提交，不依赖后台额度或定时器；仍计入本轮正常工具预算 |
| 空闲一小时 | 会话最后一次前台有效活动结束且无活动/排队输入后 | 仅该会话的新输入/活动重置到期时间；其他会话不推迟它。候选按Bot合并处理 |
| 自动或手动压缩成功 | 摘要、revision和覆盖范围持久化的同一事务 | 同事务登记证据范围，事务外后台提取；原始Entry仍保留，摘要不是事实来源 |
| Task成果回报 | 同Bot派生Task完成已验证工作并持久回报时 | 登记候选，等待该会话空闲或压缩触发；不新增“每次回复就立即总结”规则 |
| 用户手动“整理记忆” | 记忆页或主会话请求 | 立即排队处理未消费候选，使用同一后台预算与去重流程 |

不新增默认“每10轮”触发；一小时是本产品已确定的默认。空闲到期时没有新材料则不调用模型，整理作业/通知/状态轮询本身不重置空闲时间。

持久队列至少记录：jobId、botId、sourceTaskId、trigger、原始Entry/工具回执引用、压缩revision或结果revision、证据指纹、dueAt、状态、重试次数、模型配置快照和用量。沿用现有Harness存储，状态包括pending/running/applied/no-change/retry-wait/blocked/cancelled。以已处理证据和提交回执去重，不以“最大EntryId”跳过中间失败内容。

- 同一证据被空闲、压缩、任务回报多次命中，最多产生一次相同事实的有效写入；同Bot每次只执行一个整理作业，共享偏好写入做版本校验和合并。
- 原始证据已固定时，压缩整理可在业务Task继续执行期间排队；前台用户输入优先，可暂停/取消后台请求，留下可恢复状态。后台没有执行原Task工具的能力。
- 重启按已保存时间和证据恢复；已到期作业有界处理，不重等完整一小时，也不一次性扫描所有历史启动大量调用。
- 失败、额度不足、结果未解析不推进成功水位；确定未提交的作业有界重试。提交结果不确定时先查持久回执，再决定续办，不盲目重复写入。
- 默认沿用现有UTC日20次/120000 token独立预算、每批8条/12000字符和2048输出token；超过一批的候选分批续办，不因第一批完成而丢失后续材料。已用额度不随服务重启清零。
- 使用所属Bot当次有效模型，执行前固定配置；主模型被移除/不可用时显示待处理原因，不静默换供应商。后台用量独立于业务Task额度；主会话查看得到消耗。
- 用户停用Bot、取消有关工作、删除来源或撤销来源权限后，重新验证候选及已存派生内容。旧主会话清空按既有来源删除语义处理；仍合法的独立Task成果可以交给新主会话。

## 来源、纠正与冲突

现有自动提取只允许“直接用户原文摘录”，不足以表达Task的已验证成果。新增的是独立的候选证据契约：用户事实引用真实用户Entry；环境事实/方法引用成功的工具回执、产物版本或验证记录。模型只能提候选，宿主验证真实身份、来源关系、当前访问范围和提交版本。不能把子任务摘要复制成“认证用户原话”来绕过校验。

第一版自动学习只处理同Bot直接会话和其合法派生Task。跨Bot协作、群聊、定时任务不作为新的自动学习来源；这些已有边界不因“项目隔离弱”而失效。子Task成功状态不是事实可靠的唯一证据；失败、未知结果、仅计划过的操作、外部正文里的指令都不能变成已完成事实或长期规则。

用户明确修改优先于自动整理。无冲突新事实可自动保存，不设置逐条例行审批；等价事实合并，用户已经否定/删除的旧事实不因换触发方式复活。后台无法证明新旧事实可兼容时保留现状并标记需核实；不得静默覆盖用户手改或显式纠正。记忆是资料，不改变工具能力和授权。

## 实施票据与顺序

原始票据初始状态为 planned；本次已按依赖完整实施，当前结果见上表。用户已明确授权使用 6.1 Sol 子 Agent。

### M01　内容归属、证据和写入责任

交付：确定上述规则为正式契约；定义候选/来源类型、有效性检查、同Bot父子归属、去重和纠正优先级。显式memory_edit与自动候选入口分开，自动入口不允许模型指定任意botId/来源身份。

主要落点：`server/bot-memory.mjs`、`server/bot-memory-runtime.mjs`、`server/memory-tools.mjs`、`server/tasks.mjs`；实现时更新`docs/architecture/agent-runtime.md`、`docs/interfaces/mcp.md`与决策索引。

验收：同一条稳定事实可按新契约解释其来源；一次性语气要求不变永久偏好；Task猜测或失败回执不能保存；显式修改、文件手改、防复活、凭证过滤均保持有效。

### M02　持久队列与触发时机

依赖：M01。

交付：逐会话一小时计时、压缩提交登记、成果候选登记、手动入口；统一作业状态、租约/恢复、去重、预算与有界重试。压缩后的原始Entry引用与队列登记同事务，模型调用在事务外。关闭新后台功能后显式记忆工具仍可用。

主要落点：`server/bot-memory-runtime.mjs`、`server/context-compaction.mjs`、`server/tasks.mjs`、`server/main-session.mjs`；必要时拆出独立queue模块，避免继续堆大tasks.mjs。

验收：59分59秒无整理，满一小时仅一次；其他会话活跃不推迟；压缩无需等一小时；连续压缩同源不重复；重启恢复dueAt；失败、额度耗尽不丢候选；新用户输入不被后台排队阻塞。

### M03　统一后台回顾与长期事实整理

依赖：M01、M02。

交付：由Bot所属后台服务读取证据和现有记忆，生成结构化候选，允许“无可保存内容”；区分用户偏好、环境事实、方法候选。按版本和来源校验写入文件式记忆；跨触发等价去重，显式纠正优先，自动压缩摘要不进入长期文档。

主要落点：`server/bot-memory-runtime.mjs`、`server/bot-memory.mjs`、`server/memory-files.mjs`、`server/memory-tools.mjs`、`server/main-session.mjs`。

验收：Task的已验证环境事实经统一整理保存，下一次同Bot相关对话可用；Task无直接自动写入入口；主会话切换不串Bot；并发编辑不丢用户变更；后台未调用任何业务工具，失败不影响正常回复。

### M04　历史发现、补读与相关记忆取用

依赖：M01；与M03采用相同来源检查，M06之前完成集成。

交付：新增主会话可用的跨会话发现工具，暂名`session_search`，支持关键词、时间、分页；第一版范围为本Bot直接私聊历史及合法同Bot派生Task。普通Task保留本Task回读，不因新搜索工具获得任意会话权限。搜索命中返回有界片段和宿主绑定的回读引用，新补读入口暂名`session_history_read`；不改变task_history_read的“只读本Task”语义。

检索前限定候选范围，片段、分页、总数和补读均重新执行来源检查。索引只作可重建派生数据，先验证现有SQLite/Harness适配的可扩展方式，不私改第三方内部表或另建一套对话真源。中文关键词、代码路径、项目名必须可命中；不把英文分词可用当作中文搜索完成。

记忆注入改为稳定排序与有界相关性选择，保留全局用户偏好，按当前问题选择环境条目；可先用名称/路径/关键词匹配，无需向量服务。最新版本仍在每次调用读取，避免主会话长期不重启时看不到纠正；未注入条目可通过memory_read读取。

主要落点：`server/history-tool.mjs`、`server/tool-results.mjs`、`server/tools.mjs`、`server/policy.mjs`、`server/task-context.mjs`、`server/bot-memory.mjs`与新增search模块。

验收：“上次怎么处理这个问题”能从合法历史找到原始结果；无结果时不编造；他Bot/群聊/删除/撤权记录不泄漏内容或数量；压缩前原文仍可查；过时条目、无关项目不会挤掉当前输入；完整工具结果沿用合法resultRef补读。

### M05　将验证过的方法沉淀为Skill

依赖：M01、M03、M04。

交付：给统一整理服务提供窄范围Skill学习产物接口，输出manifest、SKILL.md及必要references，接入现有导入校验、不可变版本、内容哈希和回退。宿主分配Bot归属和可写范围；第一版仅自动创建/更新同Bot的学习产物，不自动改内置、手写或导入的第三方Skill，不自动删除Skill或新增脚本/依赖。

生成条件：过程已有成功验证、步骤可复用且说明适用条件；先检索现有Skill，更新同一方法而非每个Task生成一份日记。失败尝试不得描述为可靠流程；环境尚未配置不固化成“永远不能用某工具”。方法正文与引用材料不得包含凭证、私有外部全文或绕过权限的规则。

发布流程：先准备文件和版本，再原子登记；同Bot只自动登记符合现有能力的学习产物，依赖和所有权由宿主推导/校验，不接受模型扩大声明。复用正常Skill开关和按需激活；新生成内容不自动注入全部对话。已有活动Skill保持旧固定快照，后续激活使用新版本。用户可禁用和回退；关闭后台学习不删除已有产物。

学习版本记录来源引用与所有者；目录投影、激活、资料读取及活动规则再注入均验证来源当前可用性。来源失效时停止提供相关学习内容，保留审计和版本，不通过“已经写成Skill”绕过撤权。自动产物的注册和分配只针对所属Bot，不因现有全局Skill目录而泄漏给其他Bot。

主要落点：`server/skills.mjs`、`server/skill-import.mjs`、`server/skill-tools.mjs`、`server/capability-assignments.mjs`及新增learning模块。`skill_manage`目前是用户驱动的能力配置，不能直接借后台身份绕过它；学习产物接口与该管理入口分别定义。

验收：一次有验证依据的可复用流程可形成Skill，下次类似任务按需加载；重复回顾只更新原Skill；错误过程不发布；新Skill不授予缺失工具；用户手改冲突保留现状；落盘中断不出现半成品或重复登记。

### M06　整理反馈、兼容与整体验收

依赖：M02—M05。

交付：沿用Bot记忆页和Skill能力页，显示最近整理时间、少量变更、来源、待处理原因和用量；提供“立即整理”和暂停后台整理。默认只在有保存结果或需用户处理时提示，无新事实的例行回顾不刷屏。能纠正/忘记和回退学习Skill，不增加项目层级管理页。

兼容：新文档和索引采用可幂等的增量结构；旧PROFILE/MEMORY/USER文件、版本和修订继续可读。新队列从启用时的未处理范围开始，不默认重新学习全部旧历史；旧来源校验保持有效。若新后台实现替换旧worker，用功能开关保证同时只有一个自动整理消费者。回退关闭队列消费/新检索或Skill学习后，原对话、显式工具和文件读写仍可用；不得自动抹掉已保存内容。

主要落点：`src/BotMemory.tsx`、`src/MemoryDocuments.tsx`、`src/SkillControls.tsx`、`src/memory-api.mjs`及对应HTTP入口；正式文档覆盖架构、HTTP/MCP、操作手册与项目状态。

验收：隔离数据目录演示完整流程；pnpm test、pnpm lint、pnpm build通过；1440/375布局验证；故障注入验证重启、文件写入冲突、模型失败和额度耗尽。真实模型只在单独获准的隔离环境评估，不把模拟模型测试视为学习质量已获用户认可。

## 范围与实施前检查点

建议执行顺序：M01 → M02 → M03 → M04 → M05 → M06。先打通可靠记忆闭环，再接历史发现与方法沉淀；每票有独立回归，最终全量验收。

本计划不新增向量数据库、外部记忆provider、项目记忆空间、跨Bot知识大合并或新的执行引擎。新搜索与学习接口仍需通过既有身份和来源边界。普通业务Agent已有原生文件工具；“不提供记忆写入工具”不是文件系统沙箱，不能宣称它绝对无法改磁盘文件。后台review只获受限候选/学习产物接口，无bash和业务工具。

实施时以本计划推荐默认值推进，无需逐项重复询问。确需改变产品边界的事项再单独决策：全Bot共享知识库、群聊/跨Bot/定时任务自动学习、外部记忆服务或降低既有来源检查。当前工作树有大量上一阶段未提交修改，开工先确认基线；不把既有改动覆盖或归入本阶段独立成果。
