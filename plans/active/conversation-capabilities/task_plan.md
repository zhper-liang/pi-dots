## 1. 提问改为会话内表单，不占住整个聊天

### 用户看到的交互

- 问题以消息流内的卡片显示，不使用遮挡聊天的弹窗。默认一次问一个核心问题，确实有关联时可一次列 1–3 题。
- 支持单选、多选和文字回答；选择题保留「自己填写」。推荐项只是建议，不能自动提交或被当作用户回答。
- 卡片提供「提交回答」「稍后回答」；非必需问题可「跳过」，必需信息不能用跳过来编造答案。
- 已回答卡片折叠显示答案摘要；待答卡片可以收起，输入框始终可用。问题明确显示属于哪个请求、哪个机器人。
- 组件刷新、切换标签时保留回答草稿；页面刷新恢复已提交状态，未提交草稿按会话与问题版本在本地暂存，不收集凭据。
- 「取消这次请求」只结束该输入及其待答问题，不取消整个主会话。普通任务现有的整体取消另保留。

### 等待期间如何聊天

| 用户动作 | 预期行为 |
|---|---|
| 在表单里提交答案 | 精确回答原问题，使原请求可继续；若另一个回复正在执行，在安全边界安排恢复 |
| 在主输入框发送新消息 | 原请求保留为待补充，新的消息可以处理，不无限排在待答问题后面 |
| 选择「补充／调整这次请求」 | 将文字作为对原请求的插入，解除原等待以重新判断；失效问题标为已被替代，不伪造答案 |
| 稍后回答 | 收起问题，原请求保持待补充；不因超时自动选择选项 |
| 跳过非必需问题 | 记录显式跳过，按已说明的默认方案继续；没有安全默认值则停下依赖它的步骤 |
| 取消这次请求 | 取消关联问题、停止该输入后续动作，后面的消息仍能处理 |

普通消息默认不自动绑定为旧问题答案，避免串题；用户可以明确选择“作为该问题的回答”。真正的操作审批仍走精确审批卡，填写表单不代表批准写入或授予权限。

### 运行机制

- 将问题从“占据整个 Task 的 awaitBlocker”改为“绑定具体 input 的持久待答记录”。保留原 Task 身份和唯一 Harness；同一 Task 同一时刻仍只有一个执行段，不新增平行执行引擎。
- 问题登记完成后释放可执行输入位置，保存原输入的恢复信息；普通队列可推进。回答使原输入进入可恢复队列，每个请求只入队一次。
- 恢复调度规则：不抢占已派发工具；已提交的答案或调整在下一个安全边界优先恢复，其后处理普通 FIFO 队列。多个恢复项按到达顺序，不静默丢弃普通消息。
- 不再用一个全局 activeId 决定所有问题是否可回答。每题依靠 Task、input、questionId、version、处理人定位，旧版本答案不得恢复新请求。
- 原模型一次输出中，提问后尚未执行的工具继续按现有规则关闭并记录跳过；恢复时重新规划，不重放旧写操作。
- 原输入恢复时恢复其模型选择、调用额度、Skill 与上下文边界；临时处理新消息不能把另一输入的配置带回来。历史里已经成功的操作不重做。
- 服务重启后可重建待答表单和可执行队列；不会因恢复重复提交答案、重复消费消息或执行副作用。

### 数据与兼容

- 优先扩展现有 TaskBlockers 和 resolve 接口，新增结构化题目、稳定选项 ID、必填/可跳过属性、处理动作和 requestId；保留旧 question / answer 文本兼容投影。
- 表单答案保留结构化值及可读摘要；服务端校验题目版本、选项范围、必填字段、处理人和幂等键。重复请求返回原回执，冲突答案明确报错。
- 旧单文本问题显示为一题表单；旧 awaitBlocker 在临时数据库中验证转换，保持原工具调用关联。
- 主会话、普通会话、群内问题、子任务镜像共用表单组件。受管子任务仍由绑定主管处理；展示位置不能改变谁能答、谁能插入或返工。
- 提示词同步更新：可用工具或上下文能查到的信息先查询；只为影响继续执行的缺失信息提问，不把“请授权”当成信息问题。

## 2. 能力保存后，同一会话知道并能用

### 先定位，后修复

已有代码在每次模型调用和工具派发时读取 ToolAccess。当前尚未重现具体失败，不把原因预设为旧权限快照。用已有会话和假模型验证以下链路：

1. 用户开关是否保存到正确机器人，返回的版本是否更新。
2. 工具分配、已撤销项、来源分配与排除项是否一致。
3. 连接是否可用，以及最终发给模型的 schema / 来源描述是否包含新能力。
4. 模型调用工具后，实际派发检查是否允许且结果正确。

### 目标行为

- 保存成功后更新能力页、会话详情、工具标签和连接状态；所有入口共用失效通知，不只刷新当前面板。
- 服务端统一计算“配置已开启”和“当前实际可用”。不可用时说明具体原因，如未连接、缺凭据、来源未分配、权限已收窄或目录待复核；不把已勾选显示成已经可用。
- 每次模型调用前，将当前实际可用工具、资源范围和变更后的简短状态交给模型；覆盖历史里“没有权限”的旧结论，不改写历史消息。
- 变化摘要以服务端复核结果生成，并覆盖压缩恢复场景；不能让用户消息、模型文字或第三方工具结果伪造能力变化。
- 保存后提示「已保存，当前会话下一步可用」。若模型调用已在途，提示「下一步使用新能力」；不能承诺修改已经发送出去的请求。
- 空闲会话不因一次配置保存自动调用模型；下一条消息立即使用新能力。等待信息的会话保留表单，不把授权变化冒充答案；用户可直接插入「按新能力继续」。
- 撤权从下一次实际派发检查起生效；已发出去的请求按原结果处理，不能承诺撤回。断连和来源收窄时及时隐藏过期的敏感内容。
- 会话、能力和诊断页通过进入、窗口恢复焦点、网络恢复、保存通知及后台定时检查自动同步；不常驻刷新按钮，后台读取保留内容，失败时自动重试并提供重新读取。不重跑任务、不重发工具、不清空聊天和输入草稿。

## 3. 删除重复的本地读取授权

- 「帮我想办法」只保留功能开关和简短用途说明。
- 删除「pipi 能查看本地待办和日程（只读）」状态句、附带勾选框和由此产生的额外保存操作。
- 本地读取、日程和待办能力统一从「能力 → 工具集 → 日程与待办」读取。
- 后端移除 assist-setting 隐式调用 grantChiefRead 的路径；旧 chiefRead 写入字段明确返回已迁移提示，不保留隐藏的第二套授权。只读兼容字段若仍有调用方，可短期派生返回。
- 不撤销用户已有权限，也不借迁移自动扩大权限。帮我想办法仍限制为只读分析，无能力时基于提醒卡内容说明限制并提供能力入口。

## 4. 状态自动加载，诊断按需展开

- 打开设置或能力页时，自动读取连接与来源的轻量摘要；展开存储诊断时自动读详情，不要求先点「读取存储状态」。
- 保存能力、连接成功、断开/换绑、页面重新获得焦点、网络恢复时主动更新关联状态。
- 复用 useWorkspaceRefresh 的可见性、并发去重和迟到响应保护；合并飞书多个面板的重复轮询，后台隐藏面板不持续请求。
- 初次加载显示短提示；同一身份下刷新保留最后一次摘要并标注更新时间，失败显示重试。撤权、切换账号或来源时清掉旧来源敏感信息。
- 业务存储和外部来源分开报告结果：外部暂不可达不能把本地存储一起显示成失败。
- 自动读取只读取状态，不自动连接、重新授权或查询日程正文；不改变已经配置的后台日历同步任务。
- 仅读取失败时提供重新读取作为补救，技术字段放进诊断详情。

## 5. 飞书统一进入能力页

保留现有「工具集 / MCP / Skills」分类。飞书作为「日程与待办」内部使用范围中的一行，不另造独立平级面板。

```text
能力 → 工具集
  日程与待办                         [开关]
    使用范围
    [✓] 本地待办与日程
    [✓] 飞书日历 · 工作日历 · 已连接          [管理连接]
    （未连接时显示：飞书日历 · 未连接           [连接]）
```

- 日程与待办控制业务工具；来源勾选控制当前机器人的资源范围，复用 excludedResources 等现有来源收窄规则。总工具集关闭时保留勾选并禁用，说明重新开启后生效。工具集只启用部分工具时显示「部分」和明确说明。
- 「管理连接」就地打开共享配置面板，集中展示凭据是否配置、选择/绑定日历、连接状态、重新检查和断开。全局连接与“这个机器人能用”明确区分；断开前展示受影响机器人。
- 沿用已连接来源向持有日程与待办工具的机器人分发的现行规则，并保留用户已有排除项；不趁入口迁移改成全员启用。
- 整合 SettingsPage 的飞书管理和 BotTemplatePage 的旧 FeishuCalendarPanel；旧入口只提供跳转，配置表单只维护一份。
- 日程查询和编辑回到「事项 → 日历」；测试容器管理和技术状态放高级诊断，不占常用能力卡片。
- Google / MCP 接入复用同一连接组件入口；本轮不重做 Google 授权流程，不新增连接器。工具集、MCP 和 Skills 的权限规则保持各自现有语义。

## 验收清单

| 场景 | 必须满足 |
|---|---|
| 问题未回答，发送新问题 | 新问题能被处理，旧表单和原请求保留，无无限等待 |
| 问题未回答，插入调整 | 调整到达对应原输入，旧问题正确替代，不冒充已回答 |
| 单选、多选、文字、自己填写 | 校验明确；推荐项不自动提交；可跳过与必需题行为一致 |
| 原请求 A 等答，处理 B 后回答 A | A 恢复自身上下文、模型选择和 Skill，不混入 B 的执行状态 |
| 答案重复提交、过期版本、双页面竞争 | 只恢复一次；冲突明确；不重复业务写入 |
| 等待期间刷新页面或重启测试进程 | 待答问题、队列和已提交答案可恢复，聊天不永久锁住 |
| 开启能力后继续旧会话 | 无需新建会话；下一次模型 schema 和来源正确，实际调用成功 |
| 已开启但未连接或范围不符 | 显示真实原因，模型不会虚报可用 |
| 模型调用在途时开关能力 | 新增能力在后续调用可见，撤销能力在派发前被拒绝 |
| 能力变更后处于待答状态 | 表单不丢失，刷新不重跑；可插入调整后使用最新能力 |
| 帮我想办法开关 | 不修改 ToolAccess；无旧权限勾选框，分析保持只读 |
| 进入设置/能力/诊断 | 状态自动加载，离线可恢复；不自动连接或查询正文 |
| 飞书连接、停用、换绑、来源排除 | 所有入口一致，老来源内容清理，排除项不被重新授予 |
| 群聊、主管与子任务 | 题目归属清楚，未扩大回答、返工、审批权限 |
| 宽屏与 375px 窄屏、键盘和中文输入 | 表单不遮挡输入框、不横向溢出；回车、输入法和焦点行为正确 |

测试以临时数据库、假模型和假外部服务完成，重点捕获实际模型请求和工具派发，而非只检查字符串。实现后运行 `pnpm test`、`pnpm lint`、`pnpm build`，并显式运行 package.json 未覆盖的相关前端行为测试。真实模型表现和飞书账号验证单列结果，不能由假服务通过推断为通过。
