## 合并原则与范围

按完整用户闭环合并：目录/创建/持续对话归为一票，版本配置/能力池/授权归为一票，Chief 三种管理动作归为一票。迁移和停用有独立安全状态边界，分别保留；联合验收保留。每票覆盖必要的持久化、服务接口、最小网页和测试，不横向拆技术层。

01内部先做目录访问的必要预重构再增加行为，验收既有会话兼容；05只复用02和04已经稳定的业务能力接入对话工具，不同时重建底层管理。其余范围不扩张：不做跨Bot协作/群聊、真实连接器、主动任务、完整记忆系统或整体UI改版。

## 已确认的语义

- 停用阻止新工作和后续派发，不等于取消或删除；保留迟到回执和未知结果。本轮不做重新启用，不停用Chief。
- 迁移仅限无执行、待消费输入或等待事项的安全空闲边界。
- 能力池只管理当前已支持能力，扩池必须由用户明确授权；Chief不能自行扩池。

## 六张已确认票

### 01 — 创建 Bot 并持续独立对话

**合并来源：** 原01、02、03

**Blocked by:** None — can start immediately

**What it delivers:** 用户能在网页创建专业 Bot、直接对话，并按 Bot 找回历史会话和待处理事项；刷新或重启后身份与关联保持一致。

**已确认验收项：**

- 先统一 Bot 目录读取入口并持久化身份和配置，再接入动态创建；复用既有 Harness Task、conversation 和 Document，不另造执行状态机。
- 兼容现有三个预置 Bot 与历史 Task；重复初始化不重复生成身份，不能以当前默认值覆盖旧 Task 快照。
- 创建只开放名称、职责和受控基础配置，不接受任意工具、资源或凭证；失败或重复提交不产生半成品与重复 Bot。
- 新 Bot 可直接接单，无需 Chief 转发；清楚区分继续旧会话与新建会话，不自动合并已有会话。
- Bot 之间的历史、队列、Skill、工具产物、问题和审批不串用；错误关联被拒绝，异步网页回包不能污染另一 Bot。
- 完整覆盖目录兼容、创建接口、回复、网页切换、断线与重启回读；不重做已有单 Task 功能。

### 02 — 配置 Bot、授权能力并即时撤权

**合并来源：** 原04、05、06

**Blocked by:** 01

**What it delivers:** 用户能在详情页调整 Bot 角色、模型及工具/资源权限，明确看到新旧配置；系统授权由用户控制，撤权实时约束所有相关执行。

**已确认验收项：**

- 仅开放既有运行时支持、已配置的模型和模拟工具/资源；不新增供应商、连接器或依赖，不暴露凭证。
- 配置保存产生不可变版本及来源，过期编辑不能覆盖新版本，失败不部分生效；新 Task 用新配置，旧 Task 保留快照。
- 网页区分工具已安装、用户能力池已授权、Bot 已分配与 Task 固定权限；系统注册工具不等于用户授权。
- 用户通过独立明确操作扩池；Chief、普通消息和业务动作审批不能扩池。扩池不自动给 Bot 或旧 Task 增权。
- Bot 分配只能取授权池内工具和资源的子集；新增权限只对新 Task 生效，移除 Bot 权限或池级授权立即约束旧 Task 的下一次派发和恢复。
- 配置变更、授权、拒绝及撤销均可回读审计；重复授权请求幂等，资源越界和篡改输入被拒绝。
- 用新旧 Task、不同 Bot 和模拟读写动作展示版本及权限边界；写入继续要求精确审批，覆盖并发撤权、旧审批与重启。

### 03 — 旧会话安全迁移到新配置

**合并来源：** 原07

**Blocked by:** 02

**What it delivers:** 用户查看差异并明确确认后，能在安全执行间隙让同一会话采用新配置继续工作，同时保留历史、进度与用量。

**已确认验收项：**

- 只允许无执行、无待消费输入、无审批/阻塞/结果未知等待的空闲边界迁移；忙碌时拒绝，不暗中排队实施。
- 校验目标版本、模型容量、实时授权和固定活动 Skill 依赖；不兼容时明确拒绝，不静默丢弃规则或扩大权限。
- 保留原 Task/conversation、历史、任务要求、成功回执与累计用量；记录前后版本和认证用户来源，普通消息不触发迁移。
- 迁移和执行准入防竞态，失败原子回滚；覆盖重复提交、撤权、重启一致性及迁移后真实回复。

### 04 — 停用 Bot 并保留历史与在途结果

**合并来源：** 原08

**Blocked by:** 01

**What it delivers:** 用户可从网页停用专业 Bot，阻止新工作和后续派发，同时继续查看历史、待处理事项及已发生动作的真实结果。

**已确认验收项：**

- 停用规则：禁止新建 Task、新输入执行及后续模型/工具派发；停用不等于取消或删除，本轮不做重新启用、不停用 Chief。
- 在途请求尽力停止；迟到真实回执如实保存，已经发生的效果不伪称回滚，未知结果仍保持未知。
- 普通消息、业务审批、配置迁移和重启不能解除停用；历史可查看，原取消入口仍可用。
- 以已有专业 Bot 即可演示空闲/执行/等待状态下停用，覆盖网页状态、服务端准入、恢复和回执一致性。

### 05 — Chief 对话完成 Bot 创建、调整与停用

**合并来源：** 原09、10、11

**Blocked by:** 02, 04

**What it delivers:** 用户用自然语言让 Chief 创建、配置或停用专业 Bot，实际结果同步反映在网页中，可直接进入目标 Bot 或查看管理记录。

**已确认验收项：**

- 三种管理动作共用已完成的管理服务与契约，不另写一套配置、授权或停用逻辑；本票只增加受控对话入口、工具回执与对应展示。
- Chief 先明确目标和变更内容，必要信息不足时使用既有提问闭环；不臆造授权，不默选模糊目标。
- 服务端验证 Chief 身份和管理工具权限；提示词自称 Chief 无效，管理权不等于业务执行权或所有任务的主管职责。
- 只能在用户授权池内配置，不允许扩池、不自动迁移旧 Task，停用行为与网页入口一致。
- 每个管理操作使用稳定标识和持久化回执；重试、恢复及重复结果读取不重复创建 Bot、生成配置版本或施加动作；过期修改必须重新决策。
- 保留发起用户、执行 Chief、关联 Task、目标 Bot、前后版本及结果来源；创建返回直接入口，停用保留可查看历史。
- 真实模型分别展示创建、调整和停用；自动测试覆盖越权、目标歧义、并发编辑、重复管理请求、执行中停用及重启。

### 06 — 多 Bot 与 Chief 管理联合验收

**合并来源：** 原12

**Blocked by:** 03, 05

**What it delivers:** 完整演示 Chief 管理两个专业 Bot、分别长期对话、授权和迁移、停用与恢复，验证所有能力组合后仍保持原运行安全约束。

**已确认验收项：**

- 前五票各自包含必要的持久化、接口、最小网页和测试；本票只做组合验收，不是补齐前票基本功能或测试的兜底。
- 真实模型网页演示创建两个专业 Bot、直接接单与继续会话、修改配置、新旧版本、用户安全迁移、撤权和停用。
- 交叉验证 FIFO、显式插入、三选一审批锁卡、新动作新审批、Skill、预算、取消终态与未知动作结果；跨 Bot 不串上下文和控制事项。
- 使用隔离数据验证断线、崩溃窗口、重复提交、同时编辑与重启；真实模型证据和确定性故障夹具分别标注，不操作正式数据库或泄露凭证。
- 全量自动测试、lint/build及桌面/移动网页验证通过；记录本轮真实结果，不把历史368项基线冒充新增验收。
