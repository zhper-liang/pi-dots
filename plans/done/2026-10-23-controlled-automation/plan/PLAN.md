## 1. 北极星与可检验含义【定】
以对话为主入口、创建门槛低、低风险可自动、高风险有硬禁止兜底的可控自动代理。
- N1 对话为主入口：只读提问、派活、批准/拒绝、看进度、撤销自动改动、暂停全部自动化、建 Bot、提议例行任务，都能在对话里完成，不必打开管理页。
- N2 创建门槛低：建 Bot 只填名字；派活一句话；某类动作以后自动执行，只需在审批卡上点一次"总是"。
- N3 低风险可自动：R0、R1 默认不出审批卡；R1 自动执行后留可撤销卡，受每小时上限约束。
- N4 高风险有硬兜底：H 必出卡且不能放宽，R4 一律拒绝；靠代码硬匹配，不靠模型判断；有专项测试证明任何规则、档位、"总是"、暂停组合都放不开。
- N5 可控：一键暂停全部自动化；自动改动可撤销；每个 Task 有时间线；无人值守产生的审批会过期。

## 2. 术语
|术语|含义|
|---|---|
|主会话|每个 Bot 一个常驻 chat Task（card.kind='main'），是与该 Bot 对话的入口；只带只读工具和派活工具|
|派生 Task|主会话通过 task_create 建出的独立 Task，执行者就是该 Bot 自己|
|任务线程|改造前已有的普通 Task，原样保留，列在该 Bot 下|
|TaskDigest|每个 Bot 一份：派生 Task 的一行概述；Task 结束标 over，主会话下一轮读入并在回复成功提交后删除；不是记忆|
|系统卡|追加到会话里的系统条目；不进输入队列、不唤醒模型、不计额度|
|镜像卡|派生 Task 的审批、补充信息、结束、自动执行，在主会话里显示的系统卡|
|在场/无人值守|Task 的 card.origin：'user' 表示由用户输入发起，为在场；'routine'、'detector'、'event' 为无人值守|
|policy 层|`server/policy.mjs`：风险登记表加 decide()，是所有工具调用的唯一裁决入口|
|规则表|allow/ask/deny 的唯一依据；档位只是写入一组预设规则|
|Finding|检测器的发现：对象引用加版本，带状态|
|例行任务|挂在某个 Bot 名下的 Schedule|

### 3.3 decide() 的顺序【推，依据 N4】
decide() 只裁决 allow/ask/deny。能力检查（Grant、authority.authorize、Task 固定许可、撤权）照旧先跑，decide() 不替代它们。
输入：bot、task（含 origin、本输入已改动的本地条数）、tool、action、sourceId、type。
1. 命中 R4：deny。
2. 工具未登记：deny。
3. 等级为 R0：allow。
4. 在规则表里取最具体的匹配：tool+action+source+type > tool+action > 风险等级。同样具体时 deny > ask > allow。没有匹配时为 ask。
5. 等级为 H，或本输入的本地改动已满 5 条：把 allow 降为 ask，卡上不出"总是"。
6. 全局暂停中，或该 Bot 近 60 分钟自动写入已达上限（P-01）：把 allow 降为 ask。
7. 返回 {effect, risk, reason}。ask 时，在场与否按 card.origin 判断（P-06）：在场按现有审批时效，无人值守的审批 30 分钟过期。
第 4 步按"最具体"取规则，是为了让审批卡上点的"总是"（具体规则）能盖过档位预设（按等级的规则）。硬底线由第 1、2、5、6 步保证，第 4 步放不开。

### 3.4 档位与规则【定 U-17，细节为推】
- 档位仍然决定 Grant 的能力（actions、readScope、epoch，沿用 ADR-005）；选档位时另外写入一组 origin='preset' 的规则：
  - 只能看：R1、R2、R3 deny。
  - 可以提建议：R1、R2、R3 ask。
  - 可直接改本地：R1 allow，R2、R3 ask。
- 新 Bot 默认"可直接改本地"【定 U-16】。
- 迁移：现有 allowRules（`workspace-mcp-business.mjs:146-157`）转为 origin='user' 的 allow 规则，加上 sourceId='local'。
- 现有"可直接改本地"档的 Bot，删除操作原来会自动应用（`workspace-mcp-business.mjs:76`），迁移后改为询问。这是有意的行为变化，用户已知。
- 改档位会递增 epoch；改规则不递增，规则在裁决时实时读取（与现在的 allowRules 一致）。

### 3.5 审批过期【定】
无人值守产生的 R2/R3/H 审批 30 分钟过期，过期不执行、不盲重试，状态记为 expired。在场的本地提案维持 5 分钟（`workspace-mcp-business.mjs:59`）。飞书 Task 审批维持现状。

## 4. 不变式（任何阶段都不能违反，每条都要有测试）
> 本节涉及权限与裁决的约束已被 [权限简化计划](../../../active/permission-simplify/PLAN.md) 和 [ADR-014](../../../../docs/decisions/README.md#adr-014-实时权限与直接做先问) 取代，包括固定 Task 许可、主会话只读、H/R4 硬底线、批量与小时上限、无人值守审批过期等旧规定；以下保留为历史记录。检测器、系统卡、精确意图与 unknown 不盲重试、本地撤销及暂停等仍按现行实现保留。

- I-01 R4 在任何档位、规则、"总是"、暂停组合下都是 deny。
- I-02 H 必出卡，卡上没有"总是"；写入针对 H 的 allow 规则，接口返回 400。
- I-03 所有工具调用先查登记表，写类再经 decide()；不得在别处另写放行逻辑。
- I-04 规则只按结构化字段硬匹配，不调用模型判断。
- I-05 Bot 只能降低自主度（暂停），不能提高自己或别的 Bot 的自主度。恢复暂停、改权限/档位/规则只能由用户在页面上操作；Chief 只能出确认卡。
- I-06 Task 固定许可，撤权实时生效（ADR-005）。
- I-07 检测器不调用模型，不读聊天正文。
- I-08 系统卡不唤醒模型，不计额度。
- I-09 主会话不带写工具；写入只经派生 Task。
- I-10 unknown 不盲重试；过期审批不执行（ADR-006）。
- I-11 对外写入没有撤销；设了"总是允许"的对外写入仍受每小时上限和全局暂停约束。
- I-12 TaskDigest 只放一行概述，用后即删；不加偏好、决定等字段（记忆由用户设计）。
- I-13 每次自动执行都留审计（Operation receipt 写明 autoApplied 理由）；本地自动改动一定有撤销入口。
- I-14 全局暂停期间：例行任务和事件触发不跑，恢复后不补跑；检测器照常记录；所有 allow 降为 ask；运行中的 Task 继续，但写入要询问。
- I-15 不新增依赖、不接新连接器、不提交 Git，除非用户单独同意。

### 8.0b 暂停、撤销、上限（目标 N3、N5；与 0a 合并交付）

- 全局暂停：持久开关 AutomationPause {paused, since, by, epoch}。暂停入口：设置页按钮，或主会话工具 automation_pause（R0，只能暂停）。恢复只能用设置页按钮（I-05）【推 P-05】。效果按 I-14；计划扫描跳过例行任务，恢复后不补跑；外壳顶部显示"自动化已暂停"。
- 撤销：只针对自动应用的本地改动；由用户发起，走 commitLocal，requestId = undo:<operationId>，保证幂等。
  - 新建 → 软删；修改 → 恢复 before 快照里的字段；删除 → 恢复对象。现有修改路径会拒绝已删对象（`workspace-local.mjs:168`），要新增一条内部恢复路径。
  - 当前版本必须等于自动改动后的版本，否则拒绝并提示"已被修改，不能撤销"；不设时限【推 P-04】。
  - 对外写入不给撤销，卡上写明"已发送，无法撤销"。
- 自动执行卡：每次自动应用都在所在 Task 的会话里追加系统卡"已自动做了 X｜撤销"，收件箱也留一条；阶段 1 起镜像到主会话。
- 每小时上限：该 Bot 近 60 分钟的自动写入（本地 + 外部）达到 P-01（默认 20）条后，allow 降为 ask。
- 新 Bot 默认档位改为"可直接改本地"（U-16），与撤销同期上线。

验收：
- T0b-01 暂停后 R1 改为出卡；例行任务不触发；恢复后不补跑。
- T0b-02 Bot 调用 automation_pause 能暂停；任何 Bot 工具都不能恢复。
- T0b-03 撤销新建、修改、删除三种都能还原；版本不符时拒绝；重复撤销幂等。
- T0b-04 对外写入没有撤销入口。
- T0b-05 第 21 条自动写入出卡；60 分钟窗口是滚动的。
- T0b-06 自动执行卡、收件箱记录、审计理由三者都有。
- T0b-07 新 Bot 默认档位为"可直接改本地"，删除询问。

### 8.1 主会话（目标 N1、N2）
范围：
- BotDirectory 每项加 mainTaskId。建 Bot 时同一事务创建主会话 Task（card.kind='main'，标题为 Bot 名）；启动时给已有 Bot 补建，幂等。主会话不能取消；Bot 停用后主会话只读【推 P-12】。
- 主会话工具 = 该 Bot 已分配工具中登记为 R0 的部分 + task_create + task_status + automation_pause；Chief 另加 bot_inspect、bot_manage（受 0a 约束）。即使 Bot 被分配了写工具，主会话也不带（I-09）。
- 计额：主会话每接纳一条新输入，把当轮的 modelCalls、toolCalls、totalTokens 归零，终身累计另存；有调用在途时不归零。派生 Task 照旧按 Task 计（`tools.mjs:22`、`tasks.mjs:380`）。
- task_create：
  - 参数：operationId（`^[a-zA-Z0-9_.:-]+$`，≤80）、goal（1–4000）、completionCriteria（1–20 条，每条 1–1000）；没有 botId，执行者就是本 Bot。
  - 幂等键 = mainTaskId:entryId:operationId，加参数签名；同键不同参数返回冲突，同参数重放返回原回执。
  - Bot 停用时拒绝；本 Bot 运行中的派生 Task ≥ P-07（默认 5）时拒绝，返回错误让模型告诉用户。
  - 像 createChatTask（`task-creation.mjs:25-64`）一样快照 Bot 当前配置和权限；首条输入用简报格式（同 `collaboration.mjs:59`）；card 记 mainParent {mainTaskId, entryId, operationId}、origin='user'。
  - 不进 Collaboration，不阻塞主会话；同一事务写 TaskDigest；立即返回 {taskId, href}。
- task_status：只读，只能查本主会话派出的 Task（状态、待审批数、结果摘要）。
- TaskDigest：每 Bot 一个 doc，items[{taskId, summary≤80字, createdAt, state: running|over, overAt, outcome: succeeded|failed|cancelled, consumingEntryId?}]。
  - 何时算 over【推 P-21】：派生 Task 的首条简报输入处理完（成功或失败），或 Task 被取消（挂点 `tasks.mjs:124`、`tasks.mjs:722`）。之后用户在派生 Task 里继续聊，不再写回 Digest。
  - 消费：主会话构造模型请求时，把 over 且未消费的条目作为一条系统说明注入，并记下 consumingEntryId；回复提交成功的同一事务里删除这些条目；失败或 unknown 时清掉 consumingEntryId，留给下一轮。
- 镜像卡：派生 Task 出现待审批、需要补充、结束、自动执行时，在主会话追加系统卡；卡上的批准、补充、撤销直接调用现有接口，不新增审批逻辑。
- 前端：侧栏里每个 Bot 点开就是它的主会话；任务线程和派生 Task 列在该 Bot 下；渲染系统卡。

验收：
- T1-01 每个 Bot 恰好一个主会话；建 Bot 与补建原子且幂等。
- T1-02 主会话工具集合正确；分配了写工具，主会话也没有。
- T1-03 task_create 幂等、冲突、只能派给自己、停用拒绝、并发上限。
- T1-04 派生 Task 运行时主会话照常回复（不等待）。
- T1-05 首条输入完成、失败、取消都标 over；回复提交成功才删除；失败或 unknown 保留并在下一轮重新注入。
- T1-06 镜像卡不唤醒模型、不加计数。
- T1-07 主会话超过 25 轮仍能对话；派生 Task 计额不变。
- T1-08 派生后撤权，派生 Task 按 ADR-005 失效关闭。
- T1-09 主会话不能取消；Bot 停用后只读。

### 8.2 检测器（目标 N1、N3 中的只读主动性）
范围：
- 变化标记：本地待办、日程、关联的写入都经 applyLocalConfirmed（`workspace-local.mjs:156`）落库，开工时复核没有旁路；外部同步在落库处（`workspace-sync.mjs:93-108`）。两处都在同一事务写 DetectorDirty {sourceId, type, id}。
- 后台 worker：去抖 P-09（默认 2 秒）后消费，只重算受影响对象相关的检测；算出最近的时间边界，维持一个内部唤醒（复用 Schedule，callLimits 全为 0）。日界线按 P-10（默认 Asia/Shanghai，与 `inbox.mjs:10` 一致）。
- 检测器：
  - 冲突：未来 P-08（默认 7 天）内两个未删除日程时间重叠（首尾相接不算）。来源为本地，加有完整读权限的外部来源；只有忙闲权限的来源也参与，显示为"忙碌"；全天事件不参与；外部来源数据不完整或过期时，该来源不参与，卡上注明"数据不全"。
  - 逾期：待办未完成、未删除，且已过截止时间；或今天截止且今天剩余空闲少于 30 分钟。
  - 会前未准备：日程在 12 小时内开始，并且有经 ItemLink 显式关联的待办未完成；不推断其他关联。
  - 昨日遗留：每天 08:00 后第一次唤醒时生成一张汇总卡：昨天及更早未完成的待办、pending 的用户 blocker 和审批、昨天过期的提案、被顺延的 Finding。
  - 话题跟进：assignee=user 的 pending blocker、pending 审批、主管验收未完成，超过 4 小时未处理；指向原 Task。
- Finding：{id, detector, refs:[{type, sourceId, id, version}], dedupeKey=hash(detector, refs), state: open|dismissed|muted|resolved|deferred, createdAt}。任一 ref 版本变化、被删除或完成时，旧 Finding 静默标 resolved，再按新状态判定。
- 投递：每条 Finding 写一条 Notification；22:00–08:00 之外，同时在 Chief 主会话追加系统卡；当天第 11 条起标 deferred，并入次日汇总。汇总卡本身不计入 10 条。
- 卡片动作：处理 = 在 Chief 主会话派生一个预填目标的 Task（origin='user'）；忽略 = 这个版本不再提醒；这类别别再提醒 = 屏蔽该检测器（设置页可恢复）。

验收：
- T2-01 本地写入与 DetectorDirty 在同一事务；写入回滚时标记也回滚。
- T2-02 冲突：重叠、首尾相接、7 天边界、只有忙闲权限的来源、过期来源。
- T2-03 逾期与今天剩余空闲不足。
- T2-04 会前未准备只认显式关联。
- T2-05 同一版本只提醒一次；版本变化后重新判定。
- T2-06 夜间只进收件箱；第 11 条顺延进汇总；汇总每天一次。
- T2-07 话题跟进：4 小时边界；每个对象版本一次。
- T2-08 数据不变时，到点唤醒仍能触发逾期和会前提醒。
- T2-09 断言：检测全程 modelCalls 为 0，不读取会话正文。
- T2-10 处理、忽略、屏蔽三种动作，以及在设置页恢复。
