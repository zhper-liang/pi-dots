# 第四轮文案

## 1. 规则

1. 一条提示只说一件事，一句话，尽量 40 字以内。说不清楚或用户不需要知道的，删掉。
2. 不写"不会… / 不代表… / 不能当成…"式的免责说明；真要提醒，就正面说该怎么做。
3. 不写实现细节（requestId、版本号、快照、epoch、Task、回执、幂等）。这些只放进 `tech-info`；`tech-info` 里的文字可以保留技术词，不要求改。
4. 出错和恢复：说发生了什么、点哪个按钮。例：「没确认保存成功，点「重试」。」
5. 统一用词：机器人（Chief 仍叫 Chief）、会话、定时任务、日历和任务列表、能力、工具集、技术信息、通知 / 提醒。
6. `aria-label`、`title`、`placeholder` 也算界面文字。
7. 字符串写在哪个文件，就由拥有该文件的票改（README §4.2）。服务端只改 CONTRACTS §3.3、§4.8 列出的句子。
8. 下面没列到的句子，按 1–6 自己改。`ui-audit.mjs` 查出的遗留，W2 主管改。

## 2. 禁用词

`ui-audit.mjs` 打开所有非 `.tech-info` 折叠后，在可见文字里查这些词，命中就不通过。

| 禁用 | 换成 |
|---|---|
| 单独的 `Bot` | 机器人 |
| 单独的 `Task` | 会话或任务（看上下文） |
| 来源 | 日历和任务列表 / 连接；记忆里的"来源对话"→「原对话」 |
| 资源 | 日历和任务列表 |
| 例行任务、简报 | 定时任务 |
| 工具组 | 工具集 |
| 回执 | 结果 |
| 快照、审计、幂等、epoch、requestId | 删掉，或挪进 `tech-info` |
| 真实模型、模拟日程 | 删掉 |
| 先问、直接执行、写入确认 | 删掉；全局暂停时的确认写「需要你确认」 |
| 不会、不代表 | 改成正面说法，或删掉整句 |
| `workspace.…`、`mcp_<hash>` 等工具原名 | 中文工具名（UI.md R4-04） |

W2 主管另跑一遍（排除测试）：`grep -nE "资源|快照|审计|不代表|先问|直接执行|写入确认|工具组|例行任务|简报|真实模型|模拟日程|回执|幂等|来源|不会|[一-龥] ?Bot|Bot ?[一-龥]|[一-龥] ?Task|Task ?[一-龥]" src/*.tsx src/*.ts src/*.mjs`，逐条确认要么在 `tech-info` 里，要么不显示给用户。
